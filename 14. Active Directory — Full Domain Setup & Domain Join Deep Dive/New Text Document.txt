**Summary of Initial Setup and Snapshot Concept**  
- The session begins with logging into a Windows Server machine, similar to a previous setup.  
- The concept of a **snapshot** is introduced: taking a current state "snapshot" of the virtual machine (VM) allows rolling back to that state later.  
- Snapshots are very useful for testing and avoiding repeated configuration issues.  
- The machine was set up with date, time, and time zone adjustments to avoid future problems.  
- The Windows Server here is just an operating system initially without specific roles or functions.  

[00:01:29]  
**Assigning Roles to Windows Server and Active Directory Domain Services Role**  
- The procedure to assign roles to the server is explained:  
  - Go to **Add Roles and Features** in Server Manager.  
  - Select **Active Directory Domain Services (AD DS)** role.  
  - This role turns the Windows Server into a **Domain Controller (DC)**.  
- Important distinction between **Domain** and **Domain Controller**:  
  - A **Domain** is a logical boundary or namespace.  
  - A **Domain Controller** is the physical server running Windows Server with the AD DS role installed.  
- Explains that joining a machine to a domain means logically associating it with the domain, not physically moving it.  

[00:03:55]  
**Role Installation and Promotion to Domain Controller**  
- After adding the AD DS role, the next step is to **promote the server to a Domain Controller**.  
- Promotion changes the server from a regular server to a DC.  
- The server name and domain name will be configured during this process.  
- This step is essential for enabling domain-based authentication and network management.  

[00:05:59]  
**Forest, Domains, and Domain Hierarchy Concepts**  
- Introduces the **Forest** as the top-level container that can contain multiple domains.  
- Example hierarchy:  
  - Root domain: **egypt.local**  
  - Child domains: **cairo**, **alex**, **delta**, **mansoura** under egypt.local  
- Explains **Forest Functional Level** and **Domain Functional Level**:  
  - These specify the minimum Windows Server version for DCs in the forest/domain.  
  - Example: Minimum 2016 or 2012 R2 for certain features.  
- Emphasizes the use of **DNS** in Active Directory for resolving domain names to IP addresses and vice versa.  

[00:08:56]  
**Global Catalog and Read-Only Domain Controllers (RODC)**  
- **Global Catalog (GC)** stores partial information about all objects in the forest to facilitate searches across domains.  
- Introduces the **Read-Only Domain Controller (RODC)**:  
  - Contains a read-only copy of the Active Directory database without storing passwords locally.  
  - Used in locations where physical security is a concern.  
  - When authentication is required, RODC queries a writable DC for password verification.  
- Explains the use of **DSRM (Directory Services Restore Mode) password** for local admin recovery.  

[00:11:39]  
**DNS Delegation and NetBIOS Name Explained**  
- DNS delegation is used when adding child domains under a parent domain.  
- **NetBIOS** name is the short name used before the dot in the domain name (e.g., "test" in test.local).  
- NetBIOS names are used during login as **DOMAIN\username** to simplify user authentication.  

[00:12:15]  
**Active Directory Database Components: NTDS and SYSVOL**  
- The AD database is called **NTDS** (NT Directory Services), typically stored as **ntds.dit** file.  
- **SYSVOL** folder contains group policies and login scripts applied within the domain.  
- Group policy scripts can be exported and scripted via PowerShell to automate configurations instead of manual GUI steps.  

[00:17:22]  
**Prerequisite Checks and Installation Finalization**  
- Before finalizing domain controller promotion, a **Prerequisite Check** verifies network settings (IP, DNS, etc.).  
- Any errors must be resolved before proceeding.  
- Once successful, the Domain Controller installation completes, and the server restarts.  

[00:18:12]  
**Active Directory Users and Computers (ADUC) Console Overview**  
- After server promotion, use **Active Directory Users and Computers (ADUC)** console to manage AD objects.  
- AD objects include:  
  - **User Accounts:** Represent individual employees with username and password for login.  
  - **Computer Accounts:** Represent machines joined to the domain.  
  - **Organizational Units (OUs):** Containers for organizing users and computers logically (e.g., HR, Finance, Sales).  
  - **Groups:** Collections of users or computers for permission assignment.  

[00:19:50]  
**User Account Naming and Uniqueness**  
- Usernames (logon names) typically follow the format:  
  $$ \text{first\_initial}.\text{last\_name} $$  
  Example: **m.zahdi** for Mohamed Zahdi.  
- Usernames must be unique within the domain to avoid conflicts.  
- In rare cases of exact name duplication, the full last name or additional identifiers are used.  

[00:22:36]  
**Computer Accounts and Domain Join Process**  
- Joining a computer to the domain automatically creates a computer account in the **Computers** container or specified OU.  
- Computer accounts represent machines authorized to access the domain.  
- Proper organization requires placing users and computers into OUs matching their department or function, improving manageability.  

[00:25:13]  
**Group Policy and Role-Based Access Control (RBAC)**  
- Group Policy Objects (GPOs) are applied at the OU level, not directly to users or groups.  
- Permissions are assigned to **Groups**, not individual users, to simplify management.  
- Groups allow **Role-Based Access Control (RBAC)** where permissions are granted based on job role rather than individual user.  
- Example: HR group members get read-only access to HR folder by assigning permissions to the group.  

[00:28:57]  
**Core Active Directory Objects Summary**  

| Object Type            | Purpose                                | Notes                                            |
|-----------------------|--------------------------------------|--------------------------------------------------|
| User Account          | Represents employee login             | Unique username, password, personal details      |
| Computer Account      | Represents domain-joined device       | Created automatically when joining domain        |
| Organizational Unit (OU) | Logical container for organization   | Used to organize users/computers by department   |
| Group                 | Collection of users or computers      | Used for permission assignment and RBAC           |

  
[00:30:32]  
**Groups vs Organizational Units (OU)**  
- Groups are for permissions (access control), e.g., security groups.  
- OUs are for organization and applying Group Policies.  
- Permissions cannot be assigned directly to OUs; they apply to groups only.  
- Group Policies apply to OUs, not groups.  

[00:31:41]  
**Creating User Accounts and Initial Passwords**  
- Users are created inside their respective OU (e.g., HR OU).  
- Initial passwords must be **complex** (minimum 7 characters, uppercase, lowercase, numbers, special chars).  
- On first login, users must change their initial password (enforced by policy).  
- Administrators can reset passwords but cannot view user passwords.  

[00:38:37]  
**Password Policies and Expiration**  
- Password policies enforce complexity and expiration (default every 42 days).  
- Users must change expired passwords to continue logging in.  
- Policies can be adjusted (complexity requirements, expiration period) via Group Policy Editor.  
- Disabling password change or setting unified passwords is possible but not recommended for security reasons.  

[00:43:03]  
**Disabling vs Deleting User Accounts**  
- Disabling accounts is preferred over deleting for former employees to preserve data and enable recovery if needed.  
- Disabled accounts prevent login but keep user data intact.  
- Accounts can be moved to a special OU or container for disabled users.  

[00:44:30]  
**User Account Properties and Group Membership**  
- Each user account has properties including:  
  - Contact info (phone, email, address)  
  - Job title, department, manager  
- Group membership defines access rights and permissions.  
- Default membership includes **Domain Users** group.  
- Additional groups can be assigned per user as needed.  

[00:53:06]  
**User Group Management and Transfers Between Groups**  
- Users can be moved between groups when changing departments (e.g., from HR group to Sales group).  
- This involves removing the user from old group and adding to new group.  
- Group membership controls access to resources and policies.  

[00:55:35]  
**Administrator Account Best Practices**  
- The default **Administrator** account should be disabled after creating a new admin account (e.g., "NewAdmin").  
- Disabling reduces risk from common attacks targeting the Administrator username.  
- Always test new admin account login before disabling the default Administrator.  

[01:00:35]  
**Domain Join Account and Computer Account Uniqueness**  
- Computer and user accounts must be **unique** within the domain.  
- Attempting to join a domain with a duplicate computer name will fail.  
- Resolving requires renaming the computer or deleting the old computer account in AD.  
- Common troubleshooting involves **disjoin and rejoin** the domain (reset domain membership).  

[01:07:40]  
**Domain Join Authentication Process**  
- When joining a domain, the system performs:  
  1. **Authentication:** Checks username and password correctness against AD using the **Kerberos protocol** (Ticket Granting Ticket - TGT).  
  2. **Authorization:** Validates if the account has permission to join the domain (e.g., account is not disabled, password not expired).  
  3. **Accounting:** Confirms no duplicate computer account name exists in AD.  
- If all checks pass, the machine successfully joins the domain.  

[01:13:29]  
**Common Domain Join Errors and Troubleshooting**  
- Errors include:  
  - Username or password incorrect.  
  - User must change password before sign-in.  
  - Computer account name already exists.  
- Solutions:  
  - Reset or change password.  
  - Rename computer or delete conflicting account.  
- Reading and understanding error messages is critical for troubleshooting.  

[01:16:06]  
**Summary of Domain Join Background Steps**  

| Step             | Description                                                                                          |
|------------------|--------------------------------------------------------------------------------------------------|
| Authentication   | Verify username/password via Kerberos protocol                                                    |
| Authorization    | Check if user/computer account is enabled, password valid, not restricted                         |
| Accounting       | Verify no duplicate computer account with same name exists in Active Directory                    |
| Domain Join      | If all checks pass, machine is joined to domain and restart is initiated                          |

  
[01:20:19]  
**Network Connectivity and DNS Configuration Importance**  
- **Ping** command used to verify network connectivity to domain controller IP.  
- Network issues, especially **DNS misconfiguration**, are the most common causes of domain join failures.  
- DNS resolves domain names to IP addresses, essential for Kerberos authentication and AD communication.  
- Manually configure DNS server on client machines if DHCP is not used or misconfigured.  

[01:26:39]  
**Logging into Domain vs Local Accounts**  
- To login to the domain:  
  - Use **NetBIOS** or **Fully Qualified Domain Name (FQDN)** format:  
    - Example: `test\m.zahdi` or `m.zahdi@test.local`  
- To login to local machine account:  
  - Use `. \ username` (dot backslash) syntax, e.g., `. \ administrator`  
- Domain users can log into any domain-joined machine, but their permissions are limited to normal user unless granted otherwise.  

[01:29:04]  
**User Permissions and Limitations on Domain-Joined Machines**  
- Standard domain users have **normal user permissions**:  
  - Cannot install software or change network settings.  
  - Cannot modify system settings or perform administrative tasks.  
- Only users in the **Administrators group** (e.g., domain admins) have full privileges.  
- Preventing users from installing unauthorized software or changing configuration improves security and reduces risk of malware.  

[01:31:33]  
**Multiple Users Can Log Into Domain-Joined Machines**  
- Multiple domain users can log into the same machine, regardless of department.  
- Group Policies can later be used to restrict or control user experience based on OU or group membership.
